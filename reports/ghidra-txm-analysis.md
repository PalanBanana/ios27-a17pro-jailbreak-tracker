# Ghidra static analysis: TXM image, iOS 27.0.1 (build 24A446)

**Status:** research summary, data as of 2026-11-12. Target: iPhone 15 Pro Max (A17 Pro, `iPhone16,2`), iOS 27.0.1, build 24A446. Offline, static, read-only. The TXM image was taken from Apple's official firmware package. No device was connected or operated on. Method and limits are in [ghidra-kernel-analysis.md](ghidra-kernel-analysis.md). Graded evidence is in [../research/sptm-evidence-audit.md](../research/sptm-evidence-audit.md). The companion SPTM summary is [ghidra-sptm-analysis.md](ghidra-sptm-analysis.md).

This page records provenance, structure and analysis results. It does not describe how the TXM enforces anything, and it does not assess any bypass.

## 2. Structure (verified)

- Format: 64-bit arm64 Mach-O, file type `MH_EXECUTE`, 11 load commands, 6 segments: `__TEXT`, `__DATA_CONST`, `__TEXT_EXEC`, `__TEXT_BOOT_EXEC`, `__DATA`, `__LINKEDIT`.
- Source version recorded in the header: 217.0.2.0.0.
- Loaded in Ghidra with the ARM64e language variant (`AARCH64:LE:64:AppleSilicon`), selected automatically.

## 3. Analysis result (verified, with limits)

- Automatic analysis succeeded and the program was saved, with **no analyser errors** logged.
- Functions recovered: 1,654. Of these, 1,653 have default names.
- Memory blocks: 21. Symbols: about 7,100, including labels generated by the analysis. Original names are essentially absent.
- Entry points: one.
- Section names include `__info_plist`, `__exc`, `__chain_starts` and `__bootcode`. Their contents were not reviewed.

## 4. Kernel-side evidence of TXM interfaces (presence only)

The 24A446 kernelcache contains kernel log and format strings that refer to a TXM load address, and to errors on TXM thread association and disassociation. This shows that the kernel contains code paths that use a TXM interface for thread management. It does not show how those paths behave (C-083).

## 5. What this analysis does not establish

- The TXM's enforcement logic. Apple's platform guide states that SPTM and TXM are designed to work together to protect page tables (S-004). That statement is general, and this record adds no detail to it.
- Any relationship between this image and the reported SPTM bypass, which is second-hand and unverified (C-051).
- Whether the TXM behaves the same way on the A17 Pro as on other devices.
- Any vulnerability in the TXM. No function was reviewed for correctness or security.
